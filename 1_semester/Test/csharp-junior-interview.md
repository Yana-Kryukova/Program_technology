# Подготовка к техническому собеседованию: Junior C# разработчик

Этот документ поможет понять, как пройдёт техническая часть, что стоит повторить и как потренироваться заранее.

---

## 1. Как пройдёт техническая часть

**Длительность:** 40-50 минут.

Вам дадут небольшой «неаккуратный» код на C#. Ваша задача:

1. **Разобраться**, что делает код, и описать его XML-комментариями (`/// <summary>`) над классом и методами.
2. **Доработать** код под новые требования заказчика.
3. **Показать работу в `Main`**: написать небольшой сценарий, который доказывает, что код работает.
4. **Ответить письменно на 3 коротких вопроса** по теме.

## 2. Темы для повторения

### Делегаты
- Что такое делегат и зачем он нужен.
- Готовые типы: `Func<>`, `Action<>`, `Predicate<>`. Чем они отличаются.
- Собственный `delegate`: когда он оправдан.
- Multicast-делегаты (цепочка вызовов).
- Передача поведения в метод параметром.

### Лямбда-выражения
- Синтаксис, выражение и блок в теле.
- Анонимные методы и чем они отличаются от лямбд.
- Замыкания: что именно захватывает лямбда (переменную, а не значение).

### События
- `event`, `EventHandler<T>`, `EventArgs`.
- Подписка и отписка (`+=`, `-=`).
- Чем `event` отличается от публичного поля-делегата.
- Что происходит, если подписчиков нет (`null`).
- Почему забытая подписка может приводить к утечке памяти.

### Generic (обобщения)
- Обобщённые классы и методы.
- Ограничения `where` (`class`, `struct`, `new()`, интерфейсы).
- `default(T)`.
- Почему generic лучше коллекции на `object`.

---

> **Совет.** Мало прочитать, лучше написать с нуля по маленькому примеру на каждую из четырёх тем.

## 3. Учебное задание для самопроверки

Задание в другой предметной области, чем на собеседовании, но по тому же принципу. Решите его самостоятельно, затем сверьтесь с разбором в конце.

### Исходный код

```csharp
public class Book
{
    public string Title;
    public decimal Price;
    public int Year;
}

public class Reader
{
    public string Name;
    public int Age;
}

public class Library
{
    public List<Book> GetOld(List<Book> books)
    {
        var r = new List<Book>();
        foreach (var b in books) if (b.Year < 1990) r.Add(b);
        return r;
    }

    public List<Reader> GetYoung(List<Reader> readers)
    {
        var r = new List<Reader>();
        foreach (var x in readers) if (x.Age < 18) r.Add(x);
        return r;
    }

    public void Issue(Book b)
    {
        Console.WriteLine("Выдана книга " + b.Title);
    }
}
```

### Задание

1. Над классом `Library` и над каждым его методом напишите XML-комментарии. Опишите, **что** делает код, а не **как** (не «проходит циклом по списку»).
2. Требования заказчика:
   - Книги и читателей нужно отбирать по любым условиям (по цене, по имени и т. д.). Копировать метод под каждое условие нельзя.
   - О выдаче книги должны узнавать разные части системы (учёт, статистика, рассылка). Сколько их будет и какие они, `Library` знать не должен.
3. В `Main` покажите:
   - книги дороже 500, изданные после 2000 года;
   - читателей старше 60 лет;
   - выдачу книги, о которой узнали сразу два независимых «модуля»;
   - что один из «модулей» можно отключить, и он перестанет получать информацию.
